# Экспериментальная замена LG Home

**Сначала проверьте Luma отдельным приложением.** Эта страница описывает архитектуру проверенной ветки и необходимые условия отдельного внедрения. Она не является универсальной инструкцией «выполнить всё подряд». Для Home нет автоматического apply: на другом ТВ ранние root hooks могут нарушить загрузку оболочки.

## Read-only doctor

Используйте собственный уже проверенный root SSH host/alias, с проверкой ключа сервера:

```sh
ssh -o StrictHostKeyChecking=yes TV_HOST 'sh -s' < tv/launcher/takeover_doctor.sh
```

Doctor читает release, kernel/CPU, ARM32 ELF header и наличие loader, mountinfo и каталогов boot integration. Он отказывает при уже смонтированном Home или существующей Luma takeover state. Не меняет файлы, службы, UI или mounts. Успех — **частичная проверка**, не доказательство прав LS2, совместимости GPU, загрузочной цепочки или безопасного отката. Вывод не нужно публиковать целиком.

## Как работает закреплённый PR88

На webOS 5/6 upstream bind-mount'ит исполняемый файл Luma поверх `/usr/bin/com.webos.app.home`. Исходный исполняемый файл остаётся под mount; manifest, роль LG Home и регистрация SAM сохраняют системный контекст. Это не копирование Luma поверх системного бинарника. На более новых webOS используется другой метод с manifest; этот doctor его не покрывает.

PR88 также создаёт состояние в `/var/lib/luma-home`, boot hook `64-luma-home`, ранний root helper `com.webos.service.lumahome` под `/var/luna-service2` и compositor key filter. Они позволяют запустить Home раньше поздних Homebrew hooks. Обычный `home.sh enable` upstream включает эти изменения; **его нельзя считать безвредной настройкой интерфейса**. Временный mount очищается после перезагрузки, но boot hooks могут применить его снова. Поэтому одного reboot недостаточно для постоянного отката.

## Условия отдельного контролируемого внедрения

1. Проверить точный ARM32 ABI, библиотеки Luma и запуск в системном Home-контексте на целевой модели. Проверить, что LG Home — исходный системный ELF, поверх него нет takeover, и SAM manifest не был изменён.
2. Иметь root SSH, который переживает холодную загрузку, физический пульт и доступ к питанию. До изменения убедиться, что SSH действительно вернулся после обычного cold boot. Не делать единственным способом отката саму оболочку.
3. На ТВ создать приватную резервную копию **только изменяемых system integration files**: исходный Home hash, compositor filter chain/permissions, затрагиваемые LS2 service/role files и hooks/state. Зафиксировать отсутствие каждого ранее отсутствовавшего файла. Не выгружать профили/аккаунты в публичный репозиторий.
4. Проверить конфликтующие Home mappings в Input Hook и другие Home replacements. Отключать их отдельно с собственным rollback; не удалять незнакомые hooks автоматически. Не отключать LG Home preload или другие core services в рамках этой операции.
5. Сначала провести временную bind-пробу **без boot persistence**, с заранее запущенным независимым watchdog. Если за ограниченное время нет ручного подтверждения, watchdog должен снять только собственный mount и вернуть штатный Home. Сравнение source/target inode и PID/SAM identity обязательно: foreground ID сам по себе недостаточен.
6. До включения persistence дополнить **все** пути повторного применения (`early`, `boot`, `apply`, а также путь раннего helper) fail-closed guard. Нужны постоянный `DISABLE_LOCAL`, стадия `TRIAL_ARMED → TRIAL_PENDING`, одноразовый маркер текущей загрузки в `/tmp` и явный ACK. Не подтверждённый предыдущий boot, Homebrew failsafe или отсутствующий payload должны оставлять LG Home. Состояние синхронизировать на постоянное хранилище до mount. Один guard в позднем init hook недостаточен.
7. Независимый watchdog должен переживать закрытие SSH; он отключает только собственную интеграцию при потере Luma/SAM или отсутствии ACK, восстанавливает сохранённую filter chain и позволяет запустить LG Home. Оставить достаточно времени для возврата root SSH; ручной ACK давать лишь после проверки изображения и пульта. Скрипт с такими предположениями должен отдельно проверяться на целевом firmware; этот kit его не генерирует и не запускает.
8. Сравнить cold boot отдельно от Quick Start+ wake. Проверить Home из приложения и HDMI, многократный Home, настройки, звук/CEC/экранную заставку, тёплое пробуждение и холодную загрузку. Не обещать одинаковое время всем моделям. Автоматическое обновление Luma/Home scripts может стереть локальные guards — обновлять только повторным контролируемым внедрением.

## Откат и удаление

Если интеграция уже была корректно включена upstream и скрипты целы, штатные команды в root SSH:

```sh
sh /var/lib/luma-home/home.sh status
sh /var/lib/luma-home/home.sh disable
```

`disable` (также `restore`) предназначен для снятия takeover и удаления принадлежащих Luma boot/early/key-filter изменений. После этого проверить отсутствие собственного mount, запускаемый исходный Home и возврат настроек/кнопки Home; затем проверить reboot. **Сначала disable, потом удаление приложения**. Ранние hooks сохраняются при простом удалении IPK. Если disable не выполнен или повреждён, не заменять файлы наугад: отключать только заранее учтённые собственные hooks и восстанавливать файлы из своей приватной pre-change копии, сверяя metadata и hash. Пока не проверен исходный LG Home, не удалять backup.
